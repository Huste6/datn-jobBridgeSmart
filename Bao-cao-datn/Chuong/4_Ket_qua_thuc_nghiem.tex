\section{Thiết kế kiến trúc}
\label{sec:thiet-ke-kien-truc}

\subsection{Lựa chọn kiến trúc phần mềm}
\label{ssec:lua-chon-kien-truc}
Hệ thống ``JobBridge AI'' được xây dựng theo kiến trúc \textbf{Microservices} kết hợp với mô hình \textbf{Clean Architecture} (Handler -- Repository -- Model) bên trong mỗi service. Đây là sự lựa chọn phù hợp vì:

\begin{itemize}
    \item \textbf{Tách biệt trách nhiệm:} Mỗi service chỉ đảm nhận một miền nghiệp vụ duy nhất (xác thực, việc làm, AI), giúp mã nguồn dễ hiểu và bảo trì.
    \item \textbf{Triển khai độc lập:} Mỗi service được đóng gói thành Docker image riêng, có thể cập nhật mà không ảnh hưởng service khác.
    \item \textbf{Mở rộng linh hoạt:} Khi tải tăng, chỉ cần scale riêng service bị quá tải (ví dụ AI Service) mà không cần scale toàn hệ thống.
\end{itemize}

Hệ thống bao gồm 4 service backend viết bằng Go, một ứng dụng Frontend React, và một cơ sở dữ liệu MongoDB dùng chung.

\begin{itemize}
    \item \textbf{API Gateway (Port 8080):} Điểm vào duy nhất, chịu trách nhiệm xác thực JWT và định tuyến request đến đúng service.
    \item \textbf{Auth Service (Port 8081):} Quản lý người dùng, xác thực, phân quyền, upload avatar/CV lên Cloudinary, trích xuất text từ PDF.
    \item \textbf{Jobs Service (Port 8082):} CRUD tin tuyển dụng, tìm kiếm với bộ lọc đa tiêu chí, quản lý hồ sơ ứng tuyển.
    \item \textbf{AI Service (Port 8085):} Tích hợp OpenAI API để cung cấp chức năng Interview Coach, Interview Quiz và đánh giá CV.
\end{itemize}

\subsection{Thiết kế chi tiết gói (UML Class Diagram)}
\label{ssec:thiet-ke-class}
Hình \ref{fig:class-diagram} mô tả thiết kế lớp chi tiết cho các package chính. Mỗi service áp dụng mô hình Handler -- Repository -- Model:

\begin{itemize}
    \item \textbf{Handler:} Tiếp nhận HTTP request, validate dữ liệu đầu vào, gọi Repository, trả về response.
    \item \textbf{Repository:} Thực hiện các thao tác với MongoDB (CRUD), trừu tượng hóa tầng dữ liệu.
    \item \textbf{Model:} Định nghĩa cấu trúc dữ liệu (struct Go) ánh xạ với document MongoDB.
\end{itemize}

\subsection{Quy trình CI/CD và Vận hành GitOps}
Hệ thống áp dụng quy trình CI/CD hoàn toàn tự động theo mô hình GitOps, được minh họa tổng quan kiến trúc hạ tầng trong Hình \ref{fig:deployment}.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{so-do-chuong-4/deployment_architecture.png}
    \caption{Sơ đồ kiến trúc triển khai trên Azure Kubernetes Service.}
    \label{fig:deployment}
\end{figure}

Luồng triển khai diễn ra theo các bước:
\begin{enumerate}
    \item \textbf{Developer push code} lên nhánh \texttt{main} của GitHub repository.
    \item \textbf{GitHub Actions CI} tự động kích hoạt: chạy unit test, build Docker image theo multi-stage build, quét bảo mật bằng Trivy, đẩy image lên Azure Container Registry (ACR) với tag là SHA commit.
    \item \textbf{CD workflow} cập nhật file \texttt{values-azure-argocd.yaml} với image tag mới và tạo commit tự động lên repository cấu hình GitOps.
    \item \textbf{ArgoCD} (chạy trong AKS) phát hiện sự thay đổi giữa trạng thái mong muốn (Desired State) trên Git và trạng thái thực tế (Actual State) trong Cluster, tiến hành đồng bộ tự động.
\end{enumerate}

Để quản lý trạng thái đồng bộ này, giao diện quản trị ArgoCD hiển thị trực quan các tài nguyên Kubernetes được triển khai và mối quan hệ giữa chúng, được minh họa thực tế ở Hình \ref{fig:argocd-live}.

\subsection{Giám sát hệ thống (Observability)}

Prometheus chịu trách nhiệm thu thập các metric hệ thống (CPU, Memory, Network traffic, HTTP Request Rate, Error Rate), trong khi Grafana cung cấp giao diện hiển thị trực quan.

Số liệu thực tế hiển thị trên Grafana chứng minh:
\begin{itemize}
    \item \textbf{Pod Ready (\%):} Đạt mức $100\%$, chứng tỏ tất cả các bản sao (replica) của các microservice đều đang hoạt động tốt và sẵn sàng nhận request.
    \item \textbf{HTTP Error Rate 4xx/5xx (\%):} Giữ ở mức $0\%$, không ghi nhận các lỗi hệ thống nghiêm trọng hay lỗi crash server trong thời gian đo đạc.
    \item \textbf{Incoming Traffic (req/s):} Biểu đồ lưu lượng truy cập thực tế theo thời gian thực giúp quản trị viên phát hiện bất thường về tải hoặc các cuộc tấn công DDoS.
    \item \textbf{Traffic by Pod (Rx/Tx bytes/s):} Giám sát băng thông vào/ra chi tiết cho từng pod riêng biệt (Frontend, Gateway, AI, Auth), hỗ trợ đắc lực cho việc định lượng tài nguyên (Resource dimensioning) khi scale hệ thống.
\end{itemize}

\subsection{Kết quả vận hành thực nghiệm}
Hệ thống đã được triển khai thành công lên Azure AKS và vận hành ổn định. Các Pod của 4 service backend và frontend đều ở trạng thái \texttt{Running} ổn định. Thời gian phản hồi trung bình của các API thông thường dưới 200ms; các API gọi OpenAI phụ thuộc vào thời gian inference của mô hình, trung bình từ 2--4 giây. Nhờ cơ chế cache CV text, thời gian chuẩn bị dữ liệu đầu vào cho AI được rút ngắn đáng kể, giúp tăng trải nghiệm người dùng.
